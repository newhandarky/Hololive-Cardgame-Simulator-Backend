# 階段 0：對戰引擎規格文件

## 概述

本文件定義 HOLOLIVE 卡牌遊戲對戰引擎的核心規格，包括狀態機、動作合法性驗證、優先權處理、事件格式等。這些規格是實作對戰邏輯的基礎。

---

## 1. 對戰狀態機（Match State Machine）

### 1.1 對戰狀態（Match Status）

```
WAITING        → 等待玩家加入
  ↓
INITIALIZING   → 初始化（洗牌、設置起手、設置 LIFE）
  ↓
ACTIVE         → 對戰進行中
  ↓
FINISHED       → 對戰結束（正常結束）
  ↓
ABANDONED      → 對戰放棄（異常結束）
```

#### 狀態轉換規則

| 當前狀態 | 觸發條件 | 目標狀態 | 副作用 |
|---------|---------|---------|-------|
| WAITING | 雙方玩家都加入 | INITIALIZING | 無 |
| INITIALIZING | 初始化完成 | ACTIVE | 設置先攻玩家、第 1 回合 |
| ACTIVE | LIFE 歸 0 或場上無ホロメン | FINISHED | 記錄勝者、結束時間 |
| ACTIVE | 任一玩家斷線超過 3 分鐘 | ABANDONED | 判對方獲勝或雙方平手 |
| ACTIVE | 主動投降 | FINISHED | 記錄勝者 |

---

### 1.2 回合狀態機（Turn Phase Machine）

每個回合分為以下階段（Phase），必須依序執行：

```
RESET_STEP       → 重置階段
  ↓
DRAW_STEP        → 抽牌階段
  ↓
CHEER_STEP       → エール 階段
  ↓
MAIN_STEP        → 主要階段（可執行多個動作）
  ↓
PERFORMANCE_STEP → 表演階段（使用アーツ）
  ↓
END_STEP         → 結束階段
  ↓
（切換至對手回合，回到 RESET_STEP）
```

#### 階段轉換規則

| 階段 | 可執行動作 | 結束條件 | 自動執行內容 |
|-----|----------|---------|-------------|
| RESET_STEP | 無 | 自動完成 | 所有お休み狀態的ホロメン 恢復直立；コラボホロメン 回到バック |
| DRAW_STEP | 無 | 自動完成 | 從牌庫頂抽 1 張（若牌庫為空則敗北） |
| CHEER_STEP | 選擇エール送給哪隻ホロメン | 玩家確認 | 從エールデッキ翻開 1 張 |
| MAIN_STEP | 出場、Bloom、使用サポート、コラボ、バトンタッチ、使用推しスキル | 玩家點擊「結束主要階段」 | 無 |
| PERFORMANCE_STEP | 使用アーツ（センター、コラボ） | 所有可攻擊的ホロメン都已行動或玩家跳過 | 無 |
| END_STEP | 無 | 自動完成 | 清理回合內標記（如 skill_used_this_turn） |

## 2. 動作合法性驗證（Action Validation）

### 2.1 動作類型（Action Type）

所有玩家動作必須屬於以下類型之一：

| 動作類型 | 說明 | 可執行階段 |
|---------|-----|-----------|
| `DRAW_CARD` | 抽牌（自動） | DRAW_STEP |
| `ASSIGN_CHEER` | 分配エール | CHEER_STEP |
| `PLAY_MEMBER` | 出場ホロメン | MAIN_STEP |
| `BLOOM` | 進化 | MAIN_STEP |
| `USE_SUPPORT` | 使用サポートカード | MAIN_STEP |
| `COLLAB` | 執行コラボ | MAIN_STEP |
| `BATON_TOUCH` | 接力交換 | MAIN_STEP |
| `USE_OSHI_SKILL` | 使用推しスキル | MAIN_STEP |
| `USE_SP_OSHI_SKILL` | 使用SP推しスキル | MAIN_STEP |
| `USE_ART` | 使用アーツ | PERFORMANCE_STEP |
| `END_MAIN_PHASE` | 結束主要階段 | MAIN_STEP |
| `END_TURN` | 結束回合 | END_STEP |
| `SURRENDER` | 投降 | 任何階段 |

---

### 2.2 動作合法性檢查規則

每個動作在執行前必須通過以下檢查：

#### 2.2.1 基礎檢查（所有動作共通）

```java
public boolean validateBaseAction(Action action, Match match) {
    // 1. 對戰狀態必須是 ACTIVE
    if (match.getStatus() != MatchStatus.ACTIVE) {
        return false;
    }
    
    // 2. 必須輪到該玩家
    if (!action.getUserId().equals(match.getCurrentTurnPlayerId())) {
        return false;
    }
    
    // 3. 動作類型必須符合當前階段
    if (!isActionAllowedInPhase(action.getType(), match.getCurrentPhase())) {
        return false;
    }
    
    return true;
}
```

#### 2.2.2 `USE_ART` 動作檢查

```java
public boolean validateUseArt(UseArtAction action, Match match) {
    // 1. 基礎檢查
    if (!validateBaseAction(action, match)) return false;
    
    // 2. 該ホロメン 必須在場上且屬於當前玩家
    MatchHolomem holomem = matchHolomemRepository.findById(action.getHolomemId());
    if (holomem == null || !holomem.getOwnerUserId().equals(action.getUserId())) {
        return false;
    }
    
    // 3. 該ホロメン 不能是お休み狀態
    if (holomem.isRested()) {
        return false;
    }
    
    // 4. 該アーツ 必須存在於該ホロメン的卡片上
    MemberArt art = memberArtRepository.findByCardIdAndId(
        holomem.getCardId(), action.getArtId()
    );
    if (art == null) {
        return false;
    }
    
    // 5. 該ホロメン 附著的エール 必須足夠支付アーツ消耗
    Map<String, Integer> requiredCheer = art.getCostCheerJson();
    Map<String, Integer> availableCheer = getHolomemCheerCount(holomem);
    if (!hasEnoughCheer(availableCheer, requiredCheer)) {
        return false;
    }
    
    // 6. 目標必須合法（敵方センター或コラボ）
    MatchHolomem target = matchHolomemRepository.findById(action.getTargetId());
    if (target == null || target.getOwnerUserId().equals(action.getUserId())) {
        return false;
    }
    if (!target.getZone().equals("CENTER") && !target.getZone().equals("COLLAB")) {
        return false;
    }
    
    return true;
}
```

#### 2.2.3 `COLLAB` 動作檢查

```java
public boolean validateCollab(CollabAction action, Match match) {
    // 1. 基礎檢查
    if (!validateBaseAction(action, match)) return false;
    
    // 2. コラボポジション 必須為空
    MatchHolomem existingCollab = matchHolomemRepository.findByMatchIdAndOwnerAndZone(
        match.getId(), action.getUserId(), "COLLAB"
    );
    if (existingCollab != null) {
        return false;
    }
    
    // 3. 要出場的ホロメン 必須在バック且是アクティブ狀態
    MatchHolomem holomem = matchHolomemRepository.findById(action.getHolomemId());
    if (holomem == null 
        || !holomem.getZone().equals("BACK") 
        || holomem.isRested()) {
        return false;
    }
    
    return true;
}
```

#### 2.2.4 `USE_OSHI_SKILL` 動作檢查

```java
public boolean validateUseOshiSkill(UseOshiSkillAction action, Match match) {
    // 1. 基礎檢查
    if (!validateBaseAction(action, match)) return false;
    
    // 2. 取得玩家狀態
    MatchPlayer player = matchPlayerRepository.findByMatchIdAndUserId(
        match.getId(), action.getUserId()
    );
    
    // 3. 本回合是否已使用推しスキル
    if (player.isSkillUsedThisTurn()) {
        return false;
    }
    
    // 4. 取得技能資訊
    OshiSkill skill = oshiSkillRepository.findById(action.getSkillId());
    if (skill == null) return false;
    
    // 5. 若是SP技能，檢查是否已使用過
    if (skill.getSkillType().equals("SP") && player.isSpSkillUsed()) {
        return false;
    }
    
    // 6. 檢查ホロパワー是否足夠
    int requiredHolopower = skill.getHolopowerCost();
    int availableHolopower = matchHolopowerRepository.countByMatchIdAndOwnerAndFaceUp(
        match.getId(), action.getUserId(), false  // 裏面的才可用
    );
    if (availableHolopower < requiredHolopower) {
        return false;
    }
    
    return true;
}
```

## 3. 優先權與時機處理（Priority & Timing）

### 3.1 優先權規則

HOLOLIVE 卡牌遊戲為「回合制」，無需複雜的優先權系統，但需遵循以下原則：

1. **回合玩家優先**
   - 只有當前回合玩家可以執行動作
   - 非回合玩家無法執行任何主動動作（無「瞬間」卡牌）

2. **被動效果處理順序**
   - 若多個被動效果同時觸發（例如：GIFT），按以下順序處理：
     1. 回合玩家的被動
     2. 非回合玩家的被動
     3. 同一玩家的多個被動，按場上出場順序（由左至右）

3. **傷害結算時機**
   - アーツ 使用 → 計算傷害 → 檢查ホロメン是否倒下 → 若倒下則扣 LIFE → 檢查勝負

---

### 3.2 事件觸發時機（Event Timing）

某些被動效果會在特定時機觸發，系統需記錄這些時機點：

| 時機點 | 說明 | 範例 |
|-------|-----|------|
| `ON_TURN_START` | 回合開始時 | 某些推しスキル會在回合開始時觸發 |
| `ON_HOLOMEM_ENTER` | ホロメン 入場時 | GIFT 效果 |
| `ON_COLLAB` | 執行コラボ時 | 某些卡片會在コラボ時觸發特殊效果 |
| `ON_BLOOM` | 進化時 | Bloom 時的附加效果 |
| `ON_ART_USE` | 使用アーツ前 | 增傷／減傷效果 |
| `ON_DAMAGE_DEALT` | 造成傷害後 | 額外效果 |
| `ON_HOLOMEM_DOWN` | ホロメン 倒下時 | 離場效果 |
| `ON_TURN_END` | 回合結束時 | 清理效果 |

#### 事件處理範例

```java
public void processEvent(EventType eventType, EventContext context) {
    // 1. 查找所有監聽此事件的被動效果
    List<PassiveEffect> effects = getActivePassiveEffects(context.getMatch());
    
    // 2. 篩選出監聽此時機點的效果
    List<PassiveEffect> triggeredEffects = effects.stream()
        .filter(e -> e.getTriggerCondition().equals(eventType))
        .collect(Collectors.toList());
    
    // 3. 按優先權順序執行
    triggeredEffects.sort(Comparator.comparing(PassiveEffect::getPriority));
    
    for (PassiveEffect effect : triggeredEffects) {
        executePassiveEffect(effect, context);
    }
}
```

## 5. 對戰引擎核心介面（Core Interface）

### 5.1 MatchEngine 介面定義

```java
public interface MatchEngine {
    
    /**
     * 執行玩家動作
     * @return ActionResult 包含成功與否、狀態變更、錯誤訊息
     */
    ActionResult executeAction(Long matchId, Action action);
    
    /**
     * 取得當前對戰完整狀態
     */
    MatchState getMatchState(Long matchId);
    
    /**
     * 檢查動作是否合法（不執行）
     */
    ValidationResult validateAction(Long matchId, Action action);
    
    /**
     * 處理事件觸發（被動效果等）
     */
    void processEvent(Long matchId, EventType eventType, EventContext context);
    
    /**
     * 檢查勝負條件
     */
    WinConditionResult checkWinCondition(Long matchId);
    
    /**
     * 從動作記錄重建對戰狀態（用於斷線重連）
     */
    MatchState rebuildStateFromActions(Long matchId);
}
```

## 6. 實作優先順序

### 第一階段：最小可玩版本（MVP）

1. **基礎對戰流程**
   - 初始化對戰（洗牌、起手）
   - 回合階段自動流轉
   - 抽牌、エール分配

2. **核心動作**
   - 出場ホロメン
   - 使用アーツ（不含複雜效果）
   - センターホロメン 倒下 → 扣 LIFE
   - 勝負判定

3. **驗證機制**
   - 基礎動作合法性檢查
   - 動作記錄（match_actions）

### 第二階段：完整規則

1. **進階動作**
   - コラボ + ホロパワー生成
   - 使用推しスキル / SP推しスキル
   - Bloom（進化）
   - バトンタッチ

2. **效果系統**
   - 被動效果觸發
   - GIFT / COLLAB 條件效果
   - サポートカード

3. **斷線重連**
   - 從 match_actions 重建狀態
   - 狀態版本檢查

## 8. 效能與最佳化考量

### 8.1 快取策略

- **對戰狀態快取**：使用 Redis 快取當前對戰狀態，避免每次都從資料庫重建
- **卡片資料快取**：卡片基本資料（`cards`, `member_arts` 等）可永久快取

### 8.2 資料庫查詢最佳化

- 為 `match_actions` 的 `match_id` + `turn_number` 建立複合索引
- 為 `match_holomems` 的 `match_id` + `owner_user_id` + `zone` 建立複合索引

### 8.3 併發控制

- 使用樂觀鎖（Optimistic Locking）：`@Version` 欄位
- 關鍵動作使用悲觀鎖（Pessimistic Locking）：`SELECT ... FOR UPDATE`
