## 一、目前進度摘要

本輪後端優化已從「單一 God Class 內補 helper」推進到「以 effect execution family 為單位拆出 package-private service」。

目前主要成果：

- `MatchEffectService` 已從萬行級逐步降到 `8,651` 行。
- 低風險 effect family 已多數移出主 service。
- Bloom / Collab dispatcher 已逐步改成直接依賴具體 execution service，減少回頭委派 `MatchEffectService` 的 bridge。
- `MatchActionService` 目前維持 `6,099` 行，暫列第二順位。
- `MatchActionServiceIntegrationTest` 目前 `32,302` 行，暫不作為主線優先處理。

## 四、下一步優先序

### 1. 優先規劃 `DAMAGE`

原因：

- `REMOVE_CHEER` / `REMOVE_STAGE_CHEER` 已完成抽出，剩餘高收益 production 區塊開始集中到戰鬥類效果。
- `DAMAGE` 仍牽涉目標解析、傷害修正、特殊傷害、down event、life loss 與 gift follow-up，是目前風險最高但收益也最高的拆分點。
- 建議下一批不要直接搬完整 `DAMAGE`，先補 focused tests，確認可以鎖住一般傷害、特殊傷害、目標 fallback、down follow-up 與 no-op 行為。

建議下一個 commit：

```text
後端：補強傷害效果重構保護測試
```

### 2. 再拆 `DAMAGE` execution service

原因：

- 等 focused tests 補齊後，再抽 `MatchDamageEffectExecutionService`。
- 第一批可先搬 target resolution 後的 deterministic damage execution 與 summary，不要同時處理所有 down / gift follow-up。

### 3. 暫緩 `MatchActionService` 與測試巨檔治理

暫不優先處理：

- `MatchActionService`
- `MatchActionServiceIntegrationTest`

目前 production 主線仍以 `MatchEffectService` 剩餘核心 effect family 為優先。

## 五、驗證基準

每批 production 重構至少執行：

```bash
./mvnw -q -Dtest=<NewServiceTest> test
./mvnw -q -DskipTests compile
./mvnw -q -Dtest=MatchActionServiceIntegrationTest#<focused-case> test
git diff --check
```

若 integration test 因 Testcontainers / Docker / PostgreSQL socket 權限失敗，依使用者授權提高權限重跑，並在 acceptance review 中記錄。
