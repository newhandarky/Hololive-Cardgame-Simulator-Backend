## 一、目前進度摘要

本輪後端優化已從「單一 God Class 內補 helper」推進到「以 effect execution family 為單位拆出 package-private service」。

目前主要成果：

- `MatchEffectService` 已從萬行級逐步降到 `8,306` 行。
- 低風險 effect family 已多數移出主 service。
- Bloom / Collab dispatcher 已逐步改成直接依賴具體 execution service，減少回頭委派 `MatchEffectService` 的 bridge。
- `MatchActionService` 目前維持 `6,099` 行，暫列第二順位。
- `MatchActionServiceIntegrationTest` 目前 `32,302` 行，暫不作為主線優先處理。

## 四、下一步優先序

### 1. 繼續細分 `DAMAGE` 周邊高耦合 resolver

原因：

- `MatchDamageEffectExecutionService` 已承接 target resolution 後的 deterministic damage execution、summary、down 歸檔與 life loss orchestration。
- `MatchDamageEffectiveHpResolverService` 已承接 base HP、attached support HP bonus、self passive Gift HP bonus 快照解析。
- 特殊傷害免疫與 passive gift damage reduction 仍透過介面回呼或鄰近 service 邏輯處理。
- 下一批若繼續處理 `DAMAGE`，應以單一 resolver / snapshot 為單位拆分，先補 focused test 再搬 code。

建議下一個 commit：


- `MatchActionService` 仍有 turn / phase lifecycle、decision resolution flow、board action orchestration 等高密度區塊。

## 五、驗證基準

每批 production 重構至少執行：

```bash
./mvnw -q -Dtest=<NewServiceTest> test
./mvnw -q -DskipTests compile
./mvnw -q -Dtest=MatchActionServiceIntegrationTest#<focused-case> test
git diff --check
```

若 integration test 因 Testcontainers / Docker / PostgreSQL socket 權限失敗，依使用者授權提高權限重跑，並在 acceptance review 中記錄。
