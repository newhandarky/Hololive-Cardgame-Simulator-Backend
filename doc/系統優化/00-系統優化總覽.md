更新日期：2026-05-26
定位：`hololive-cardgame-backend` 後端優化主入口
用途：彙整目前進度、下一步優化方向、文件入口與文件治理規則。

---

## 一、目前狀態

本輪後端優化的主線是降低 production god class 複雜度，優先處理 `MatchEffectService`，再回到 `MatchActionService`。目前已完成一批連續、可驗證、可回退的 effect execution service extraction。

目前仍需關注的大檔：

- `src/main/java/com/hololive/cardgame/service/MatchEffectService.java`：`6,082` 行。
- `src/main/java/com/hololive/cardgame/service/MatchActionService.java`：`6,099` 行。
- `src/test/java/com/hololive/cardgame/service/MatchActionServiceIntegrationTest.java`：`32,302` 行。

本輪完成後，`MatchEffectService` 已從優化初期的萬行級核心大檔逐步下降，且多個低風險 effect family 已移出主 service。後續不再以單次小 helper 為 commit 單位，而是以「相鄰責任區」為單位拆分。

## 三、下一步優化方向

### P0：繼續拆 `MatchEffectService`

建議下一批優先順序：

1. `DAMAGE` 後續細分
   - 已完成抽出 `MatchDamageEffectExecutionService`。
   - 已完成抽出 `MatchDamageEffectiveHpResolverService`，集中 base HP、attached support HP bonus、self passive Gift HP bonus 快照解析。
   - 已完成抽出 `MatchSpecialDamagePreventionResolverService`，集中 SPECIAL_DAMAGE_IMMUNITY 查詢與 HSD13-012 stack cost 防護啟用。
   - 已完成抽出 `MatchPassiveGiftIncomingDamageReductionResolverService`，集中 passive Gift 受傷減免 target/holder 查詢、來源等級限制、骰子減免與 turn usage 紀錄。
   - 已完成抽出 `MatchAttachedSupportIncomingDamageReductionResolverService`，集中附著支援卡受傷減免查詢與 base 文案解析。
   - 已完成抽出 `MatchPassiveGiftHpChangePreventionResolverService`，集中「相手能力不能改變 HP」的回合、target、holder 與條件解析。
   - 已完成抽出 `MatchPassiveGiftArtBonusResolverService`，集中 passive Gift 藝能加成 target/holder 查詢、特殊傷害加成、holder / target 條件與歷史推し技能條件解析。
   - 已完成抽出 `MatchPassiveGiftArtCostReductionResolverService`，集中 passive Gift 藝能費用減免 target/holder 查詢、art name、cheer color、attached support 與歷史推し技能條件解析。
   - 已完成抽出 `MatchArtTextDamageBonusResolverService`，集中藝能文案自體加傷 target context、Cheer / LIFE / 推し技能歷史 / 指定推し條件解析。
   - 已完成抽出 `MatchArtDownTriggeredEffectExecutionService`，集中藝能擊倒後 follow-up raw text 擷取、clause 解析、no-op summary 與 support effect 包裝。
   - 已完成抽出 `MatchTriggeredGiftDamagePreventionExecutionService`，集中 DAMAGE_RECEIVED Gift 的 target / holder 查詢、回合使用限制、target / collab / dice 條件與 PREVENT_DAMAGE summary 組裝。
   - 已完成整理 `MatchTriggeredCombatEffectService` 的 art down bridge，讓它直接持有 `MatchArtDownTriggeredEffectExecutionService`，不再透過 `MatchEffectService.applyArtDownTriggeredEffects(...)` 中轉。
   - 已完成抽出 `MatchEffectTypeInferenceService`，集中 Bloom / Collab / Gift / ArtDown 共用 effect type 與 target type 文案分類。
   - `MatchEffectService.executeDamageEffect(...)` 保留入口與 damage redirect 分支，其餘 deterministic damage flow 委派新 service，effective HP、特殊傷害防護、passive Gift / attached support 受傷減免與 HP 變動防護不再回呼主 service。
   - 下一步可評估 Gift execution orchestration 的 sequential-cost / execution-summary 區塊，先抽出純 summary / dispatch helper，再考慮更大的 `applySupportEffect(...)` 分段。

2. 暫緩一次性完整戰鬥搬移
   - `DAMAGE` 已降低主 service 體積，但特殊傷害、down event、life loss 與 gift follow-up 仍屬高風險區塊。
   - 後續應以小型 resolver / snapshot service 為單位拆分，並先補 focused test。

### P1：回頭整理 `MatchActionService`

`MatchActionService` 目前已比 `MatchEffectService` 更穩定，但仍有 `6,099` 行。等 `MatchEffectService` 的低中風險 execution family 再收斂一批後，建議回到：

- decision resolution flow
- turn / phase lifecycle
- board action orchestration

### P2：測試巨檔治理

`MatchActionServiceIntegrationTest` 仍是最大檔案，但目前不作為主線優先處理。只有在 production 重構需要測試保護或測試定位困難時，才順手拆對應主題測試。

## 五、文件治理原則

- `00-系統優化總覽.md` 只保留目前方向、優先序與閱讀入口。
- `05-重構進度追蹤.md` 只保留目前進度摘要與近期批次，不再累積完整歷史。
- 完整歷史改放 `doc/系統優化/archive/`。
- 舊的單次開發稿與已被新文件取代的規則，歸檔到 `doc/history/archived-2026-05-25/`。
- 核心規格文件不刪除，包括 `0212-*`、REST/WebSocket/DB/對戰引擎、官方規則書、GameRoom 契約與當前 action 契約。

## 六、完成標準

本輪系統優化不以「檔案行數下降」作為唯一完成條件，而以以下四點為準：

1. `MatchEffectService` 與 `MatchActionService` 的核心責任邊界清楚。
2. 新增規則時，不必再修改同一個 God Class 的多個遠距區塊。
3. 整合測試與 smoke 驗證仍能維持既有保護力。
4. 文件入口能快速回答目前進度、下一步優先序與歷史紀錄位置。
